# 知乎提问助手

**把正在阅读的网页，变成值得讨论的知乎问题。**

提取网页素材，生成不同角度的提问，带着描述、来源和话题建议前往知乎。

[下载最新版](https://github.com/BretDeng/zhihu-question-assistant/releases/latest) · [快速开始](#快速开始) · [模型配置](#模型配置) · [反馈问题](https://github.com/BretDeng/zhihu-question-assistant/issues) · [更新记录](CHANGELOG.md)

Chrome 110+ · macOS / Windows / Linux · 自带 API Key · 无需本地服务

</div>

## 从阅读到提问

看到一篇想讨论的文章，不必反复复制、整理和切换页面。点击网页上的「问」，生成提问草稿，修改后直接送到知乎。

```text
阅读网页 → 选择提问风格 → 生成并编辑草稿 → 自动填写知乎 → 审核并发布
```

扩展负责整理和填写，最终内容与话题由你审核，发布按钮由你点击。

## 主要功能

| 功能 | 可以做什么 |
| --- | --- |
| 多角度提问 | 一次请求生成最多 6 个草稿，包含标题、问题描述和话题建议；生成过程中逐个显示 |
| 提问风格 | 切换「专业」「日常」，或保存最多 20 个自定义风格 |
| 两种描述形式 | 由模型概括材料，或直接使用网页已加载的原文，附上引用来源 |
| 多模型配置 | 支持 OpenAI 兼容 API、OpenRouter 和知乎直答；最多保存 20 套配置 |
| 知乎自动填写 | 填写标题、描述和来源，精确匹配已有话题，最多绑定 5 个 |
| 原文图片（实验性） | 识别正文里的内容图片，最多 6 张，尝试粘贴进知乎编辑器上传 |
| 减少页面打扰 | 自由拖动入口和面板；按域名停用扩展，规则包含子域名 |

## 快速开始

准备 Chrome 110 或更新版本、一个可用的模型密钥，以及用于发布问题的知乎账号。macOS、Windows 和 Linux 使用同一份扩展包。

### 1. 安装扩展

1. 在 [Releases](https://github.com/BretDeng/zhihu-question-assistant/releases/latest) 下载 `ZhihuQuestionAssistant-Extension-版本号.zip`，选择扩展安装包，而非自动附带的 `Source code`。
2. 解压到一个固定文件夹，保留该目录。
3. 在 Chrome 地址栏输入 `chrome://extensions`，开启右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。

首次安装会打开新手教程。目前通过开发者模式安装，普通使用不需要 Node.js、npm、终端或伴侣程序。

### 2. 配置模型

点击浏览器工具栏中的扩展图标，添加一套模型配置并保存。点击「展开面板」可在独立标签页使用 Dashboard。具体填写方式见下方[模型配置](#模型配置)。

### 3. 生成并提问

1. 打开文章并刷新页面，点击右下角「问」。概括模式下，也可以先选中想讨论的文字。
2. 选择提问风格，点击「分析当前网页」。
3. 编辑标题、问题描述和话题建议，点击「去知乎提问」。
4. 在知乎检查已填内容、图片和已绑定的话题，确认后自行发布。

如果尚未登录知乎，登录后手动打开提问框，扩展会尝试继续填写。自动操作失败时，草稿面板保留复制入口供手动补充。

## 模型配置

| 提供方 | 地址 / 凭证 | 模型填写 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1`；填写 API Key | 默认 `gpt-4o-mini`，或账号可用的模型 |
| OpenRouter | `https://openrouter.ai/api/v1`；填写 API Key | 平台提供的完整模型 ID |
| 其他 OpenAI 兼容服务 | 服务商的 HTTPS Base URL 和 API Key | 服务商提供的模型 ID |
| 知乎直答 | 提供方选择「知乎直答」，填写 Access Secret | 默认 `zhida-agent`；可用模型取决于账号授权 |

知乎直答密钥可前往[知乎数据开放平台](https://developer.zhihu.com/)登录，在[个人中心](https://developer.zhihu.com/profile)创建。直答请求地址由扩展固定，无需填写 Base URL。

OpenAI 兼容地址建议填写到 `/v1` 等服务入口，不必附加 `/chat/completions`。保存其他 API 域名时，Chrome 会请求对应域名的访问权限。

模型调用使用你自己的账号额度，费用与可用性由模型供应商决定。

## 按你的习惯调整

### 提问风格

- **专业**：关注原因、机制、证据、趋势和行业影响。
- **日常**：从工作、消费、生活体验和实际选择出发，减少术语。
- **自定义**：在 Dashboard「我的风格」中新建、编辑和删除，最多保存 20 个；网页面板可以直接切换。

例如，可以保存一个「上班族视角」：

> 从普通上班族的视角提问，关注收入、职业选择和生活成本。语言自然，少用术语，避免预设结论。

风格切换对下一次分析生效，已有草稿不会被改写。

### 问题描述与图片

**概括提问**由模型整理材料背景与讨论点。**网页原文**直接使用当前页面已加载、可读取的正文，不经模型改写，段落之间不留空行。两种形式都会附上引用来源。

描述与来源合计不超过 3000 字符，长文按段落优先截取。网站只加载部分正文时，也可以使用这部分内容；扩展不会绕过付费墙或读取隐藏正文。

图片功能可以在 Dashboard「原文图片」中关闭，或在知乎草稿面板取消勾选。部分图片站点需要额外授予读取权限。**自动带图目前仅通过模拟编辑器测试，尚未完成真实知乎页面验证。** 图片会尝试添加到描述末尾，不保留原文图文交错排版；下载或粘贴失败时需手动上传。转载前请确认图片使用权限。

### 网站过滤与拖动

在 Dashboard「网站过滤」中按行填写域名，例如 `example.com` 会同时排除其子域名。保存后，已打开页面上的入口和面板立即隐藏；移除规则即可恢复。

拖动「问」按钮或面板标题栏可调整位置。按钮位置会保存，也可在 Dashboard 恢复默认位置。

## 数据与隐私

- **模型请求**：点击分析后，网页标题、网址、摘要、截取的正文或选中文字，以及风格说明会发送给所选模型供应商。扩展后台直接发起请求。
- **密钥保存**：勾选「记住密钥」后存入扩展的本机存储，不是系统钥匙串加密；不勾选则仅保留在当前浏览器会话。配置与偏好不使用 Chrome 云同步。
- **图片读取**：下载时不发送 Cookie 和 Referer；支持 HTTPS 的 JPEG、PNG、GIF、WebP，单张不超过 10 MB。接受粘贴后，由知乎处理上传。
- **草稿交接**：草稿绑定到目标知乎标签页，不写入网址参数。关闭标签页或确认发布后清理；手动关闭草稿面板也会清除对应的扩展草稿。

## 常见问题

<details>
<summary>更新了安装包，为什么浏览器里还是旧版？</summary>

下载 ZIP 不会自动更新已加载的扩展。把新包替换到原目录，在 `chrome://extensions` 点击「重新加载」，核对版本号，然后刷新已打开的网页。通常无需卸载，以免丢失配置；会话密钥失效时重新填写即可。

</details>

<details>
<summary>为什么有些文章只能抓到一部分，或者找不到正文？</summary>

扩展只读取可靠正文区域中的可见内容。付费墙、未加载段落、嵌入页面或特殊排版可能限制提取。可以等待正文加载、滚动页面后重试，或改用概括模式并选中所需文字。

</details>

<details>
<summary>为什么话题没有全部绑定，或者知乎自动填写失败？</summary>

扩展只绑定候选列表中名称精确匹配的已有话题，保留已选项，不创建新话题。未匹配项需要手动选择。知乎页面变化、未登录、编辑器拒绝粘贴或字段已有内容，都可能影响自动填写；请检查面板提示，必要时使用复制入口。

</details>

<details>
<summary>生成很慢，或者提示模型请求失败怎么办？</summary>

速度取决于供应商、模型和网络。面板会逐个显示已完成的草稿，并显示首个草稿与总耗时。请核对模型 ID、API 地址、密钥权限和额度；Dashboard「常见问题与报错」支持搜索报错原文。调用失败不会自动重试计费。

</details>

仍有问题？请[提交 Issue](https://github.com/BretDeng/zhihu-question-assistant/issues/new)，附上扩展版本、浏览器版本、页面链接、报错与复现步骤。请勿提交 API Key 或其他账号凭证。

## 本地开发

扩展采用 Chrome Manifest V3 和原生 JavaScript，无运行时依赖。开发检查需要 Node.js 20+；构建 ZIP 还需要系统提供 `zip` 命令。

```bash
git clone https://github.com/BretDeng/zhihu-question-assistant.git
cd zhihu-question-assistant
npm test
npm run check
npm run build
```

在 `chrome://extensions` 直接加载仓库中的 `extension/` 目录即可调试，分发包输出到 `dist/`。

| 目录 | 用途 |
| --- | --- |
| [`extension/`](extension/) | 网页提取、模型调用、Dashboard 和知乎自动填写 |
| [`test/`](test/) | 自动测试与模拟页面 |
| [`scripts/`](scripts/) | 检查、打包与本地预览 |
| [`releases/`](releases/) | 各版本发布说明 |

运行 `npm run preview:draft` 可预览模拟界面：`/` 为知乎草稿面板，`/models?view=dashboard` 为 Dashboard，`/questions` 为网页提问面板。模拟页面不调用真实模型、不发布问题，也不能代替真实知乎页面的兼容性验证。

欢迎通过 Issue 或 Pull Request 反馈和改进。历史版本与修复细节见 [CHANGELOG](CHANGELOG.md)。
